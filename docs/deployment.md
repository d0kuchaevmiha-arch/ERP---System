# Развертывание

## Разработка / демо (docker compose)
`cp .env.example .env`, задайте `POSTGRES_PASSWORD`, `SESSION_SECRET` (случайная строка ≥ 32 символов, например `openssl rand -hex 32`), `DEMO_PASSWORD`; `docker compose up --build`. Контейнеры: PostgreSQL 16 с постоянным volume и приложение Next.js 16 на порту 3000. Healthcheck `/api/health`.

При старте контейнер приложения выполняет `scripts/migrate.ts` (версионные миграции; для volume, созданного прежней версией через `drizzle-kit push`, — baseline без изменения данных, см. `database.md`), затем загрузку демо-данных (пропускается, если организация уже есть) и `next start`.

Без входа приложение данные не показывает; флаг `ERP_PRIVATE_MODE` удалён (0.2.0). Демо-пользователи: `director@monolit.local`, `manager@monolit.local` с паролем `DEMO_PASSWORD`. Новые пользователи создаются директором в «Справочники → Пользователи».

Интеграционные тесты: `npm run test:db:up` (PostgreSQL 16 в памяти на `127.0.0.1:54329`, профиль `test`, обычный `up` его не запускает), затем `npm test`.

## Перед выходом в сеть организации
**Эта конфигурация — не production.** Минимум перед подключением пользователей (подробнее — P5 спецификации):
- HTTPS reverse proxy (Caddy/nginx), приложение доступно только через него; тогда `TRUSTED_PROXY=1`, чтобы лимит входа учитывал реальный IP.
- Порт БД наружу закрыт (в `docker-compose.yml` он не публикуется), отдельный пользователь БД без суперправ.
- Секреты — в `.env` на сервере или Docker secrets, не в репозитории и не в образе (`.env` исключён `.dockerignore`).
- Резервное копирование и проверка восстановления (`backup.md`).
- Смена паролей демо-пользователей или их удаление; seed в production не запускать.
