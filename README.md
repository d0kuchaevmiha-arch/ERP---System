# Монолит · Управление стройкой

Веб-ERP для управленческого учета строительной компании. Модульный монолит: Next.js App Router (React/TypeScript, серверный API), PostgreSQL, Drizzle ORM. Локальный запуск не требует платных сервисов.

## Быстрый старт

1. Установите Docker и Docker Compose; клонируйте репозиторий.
2. `cp .env.example .env` и **замените** POSTGRES_PASSWORD, SESSION_SECRET (случайная строка не менее 32 символов), DEMO_PASSWORD.
3. `docker compose up --build`
4. Откройте http://localhost:3000 — откроется вход. Войдите как `director@monolit.local` с паролем из DEMO_PASSWORD. Без входа данные не показываются. Новых пользователей и их доступ к объектам директор заводит в «Справочники → Пользователи».
5. Повторная загрузка demo безопасна: seed пропускает существующую организацию. Для новой установки удалите volume только если данные не нужны.

Контейнер приложения применяет версионные миграции (`drizzle/`, для БД, созданных старым `push`, — baseline без изменения данных) и загружает демонстрационные данные перед стартом. Healthcheck: `/api/health`. Для сквозной проверки API после запуска: `npx tsx --env-file=.env scripts/smoke.ts` (добавляет тестовый объект).

### Без Docker

`npm ci && npm run db:migrate && npx tsx --env-file=.env scripts/seed.ts && npm run dev`. Нужен PostgreSQL и заполненный DATABASE_URL.

### Десктоп-клиент для Windows

`npm run dist` → `dist-desktop/ERP-Энерготех-Setup.exe`: локальная реплика данных своих объектов во встроенном PostgreSQL, тот же интерфейс, синхронизация с сервером (в 0.4.0 запись — онлайн, офлайн-ввод — следующий этап). Подробности, данные на ноутбуке, чек-лист — `docs/desktop.md`.

### Тесты

`npm run test:db:up` (PostgreSQL 16 в памяти на 127.0.0.1:54329), затем `npm test`. Интеграционные тесты работают с настоящей БД: изоляция организаций и объектов, гонки, миграции, сессии, управление пользователями.

### Сквозной сценарий

Войти директором → создать объект → в карточке добавить этап/работу и бюджет → добавить материал, склад и поставщика → создать заявку → согласовать → принять на склад → списать со склада → обновить прогресс работы → зарегистрировать расход → посмотреть отклонение в бюджете и скачать CSV-отчет.

## Что действительно работает

- Реальные связанные записи проектов, WBS, бюджетных статей, расходов, материалов, складских движений, заявок, договоров и контрагентов в PostgreSQL.
- Транзакционная приемка с частичной поставкой; проверка остатка под advisory lock перед списанием; стоимость списания отражается в расходах.
- Согласование заявки директором, аудит изменений, оповещения при расходе сверх бюджета и низком остатке.
- Панель директора, карточка объекта, формы, поиск по загруженным данным, CSV-экспорт.
- Вход обязателен; каждый видит и меняет только свою организацию и объекты из своего доступа (`project_access`: просмотр / ввод). Управление пользователями, блокировка с мгновенным отзывом сессий, временные пароли, лимит попыток входа в БД.
- Демо: три объекта (нормальный, перерасход, задержки), дефицит арматуры, просроченная поставка и работа.

## Важно: границы текущей версии

Это **функциональный фундамент, не завершенная «1С для стройки» и не готовая production-система**. Не реализованы: полнофункциональный Gantt/критический путь, сметные стандарты и версионирование смет, банковская интеграция, регламентированный бухгалтерский и налоговый учет, обработка фото и файлов, универсальные маршруты согласований, Excel/PDF-импорт и экспорт, проверка задолженности, техника, табель, резервирование партий и автоматические бэкапы. Интерфейс отчета CSV, а не официальный регламентированный документ. До production необходимы защищенный ingress/HTTPS, резервное копирование по расписанию, мониторинг и E2E-тесты (см. `docs/deployment.md` и спецификацию `docs/superpowers/specs/`).

## Структура

- `src/db/schema.ts` — модель PostgreSQL, ключи и индексы.
- `src/lib/seed.ts` — демонстрационные данные.
- `drizzle/` — версионные миграции; `src/server/db/migrate.ts` — применение и baseline.
- `src/server/domain/commands/` — единственная точка записи: команды с Zod-схемой, `authorize` и транзакцией; `registry.ts` — реестр и `runCommand`.
- `src/server/read/` — чтение в пределах организации и доступа (`overview.ts`, `users.ts`).
- `src/server/auth/` — пароли, сессии (`session_version`), вход и лимит попыток.
- `src/app/api/v1/[resource]/route.ts`, `src/app/api/admin/users/*`, `src/app/api/auth/*` — тонкие HTTP-обработчики.
- `test/` — интеграционные тесты на PostgreSQL 16.
- `src/components/workspace.tsx` — ERP-интерфейс.
- `docs/` — архитектура, БД, API, права, развертывание, правила, разработка, резервирование.

Управленческие показатели не являются бухгалтерскими регистрами. Интеграция с учетной системой проектируется отдельно. AI не участвует в записи финансовых данных.
