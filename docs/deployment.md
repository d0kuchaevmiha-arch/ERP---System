# Развертывание

## Разработка / демо (docker compose)
`cp .env.example .env`, задайте `POSTGRES_PASSWORD`, `SESSION_SECRET` (случайная строка ≥ 32 символов, например `openssl rand -hex 32`), `DEMO_PASSWORD`; `docker compose up --build`. Контейнеры: PostgreSQL 16 с постоянным volume и приложение Next.js 16 на порту 3000. Healthcheck `/api/health`.

При старте контейнер приложения выполняет `scripts/migrate.ts` (версионные миграции; для volume, созданного прежней версией через `drizzle-kit push`, — baseline без изменения данных, см. `database.md`), затем загрузку демо-данных (пропускается, если организация уже есть) и `next start`.

Без входа приложение данные не показывает; флаг `ERP_PRIVATE_MODE` удалён (0.2.0). Демо-пользователи: `director@monolit.local`, `manager@monolit.local` с паролем `DEMO_PASSWORD`. Новые пользователи создаются директором в «Справочники → Пользователи».

Интеграционные тесты: `npm run test:db:up` (PostgreSQL 16 в памяти на `127.0.0.1:54329`, профиль `test`, обычный `up` его не запускает), затем `npm test`.

## Реальное время (0.3.0)
Каждый экземпляр приложения держит одно дополнительное соединение с PostgreSQL (`LISTEN erp_changes`) и раздаёт сигналы браузерам через `GET /api/sync/events` (SSE). Учитывайте его в лимите соединений пользователя БД. Если соединение обрывается, приложение переподключается само (пауза до 30 с), браузеры в это время обновляют данные опросом раз в 30 с.

Reverse proxy не должен буферизовать SSE и обрывать долгие ответы: для nginx — `proxy_buffering off; proxy_read_timeout 120s;` на `/api/sync/events` (приложение шлёт heartbeat каждые 25 с и заголовок `X-Accel-Buffering: no`); Caddy по умолчанию передаёт поток без буферизации. Настройка прокси — P5.

## Десктоп-клиент (0.4.0)
Установщик `ERP-Энерготех-Setup.exe` собирается на Windows: `npm run dist` (подробности, данные на ноутбуке, чек-лист — `desktop.md`). Серверу для десктопа ничего дополнительно не нужно: те же порт и прокси. Требования к серверу организации:
- HTTPS с сертификатом, которому доверяет Windows на ноутбуках (корпоративный CA в хранилище «Доверенные корневые центры»); `http://` клиент принимает только для `localhost`.
- Прокси передаёт исходный `Host` (или `X-Forwarded-Host`) и не буферизует `/api/sync/events`.
- Docker-образ не содержит ничего десктопного: бинарники PostgreSQL для Windows — `optionalDependencies` (на Linux пропускаются), Electron при сборке образа не скачивается (`ELECTRON_SKIP_BINARY_DOWNLOAD=1`).

## Офлайн-ввод (0.5.0)
- Миграция `0004` применяется при старте контейнера: добавляет `sync_conflicts` и два поля в `users`, существующие данные не меняет. Перед обновлением сделайте дамп (`backup.md`).
- Новые маршруты: `POST /api/sync/push` (пакет до 200 операций; тело — до нескольких сотен КБ), `POST /api/auth/device/verify`. Прокси не должен ограничивать размер тела меньше 1 МБ для `/api/sync/push`.
- Обновлять сервер и десктопы можно в любом порядке внутри протокола v1: старые клиенты 0.4.0 не отправляют очередь, но продолжают работать онлайн.
- Кого назначить разбирать конфликты: у каждого объекта должен быть хотя бы один кладовщик или РП с `edit`-доступом, иначе спорные операции увидит только директор.

## Перед выходом в сеть организации
**Эта конфигурация — не production.** Минимум перед подключением пользователей (подробнее — P5 спецификации):
- HTTPS reverse proxy (Caddy/nginx), приложение доступно только через него; тогда `TRUSTED_PROXY=1`, чтобы лимит входа учитывал реальный IP.
- Порт БД наружу закрыт (в `docker-compose.yml` он не публикуется), отдельный пользователь БД без суперправ.
- Секреты — в `.env` на сервере или Docker secrets, не в репозитории и не в образе (`.env` исключён `.dockerignore`).
- Резервное копирование и проверка восстановления (`backup.md`).
- Смена паролей демо-пользователей или их удаление; seed в production не запускать.
