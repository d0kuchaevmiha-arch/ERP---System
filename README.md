# Монолит · Управление стройкой

Веб-ERP для управленческого учета строительной компании. Модульный монолит: Next.js App Router (React/TypeScript, серверный API), PostgreSQL, Drizzle ORM. Локальный запуск не требует платных сервисов.

## Быстрый старт

1. Установите Docker и Docker Compose; клонируйте репозиторий.
2. `cp .env.example .env` и **замените** POSTGRES_PASSWORD, SESSION_SECRET (случайная строка не менее 32 символов), DEMO_PASSWORD.
3. `docker compose up --build`
4. Откройте http://localhost:3000, нажмите «Демо-просмотр» справа сверху и войдите как `director@monolit.local` с паролем из DEMO_PASSWORD. Для приватного режима установите `ERP_PRIVATE_MODE=true` и откройте `/login`.
5. Повторная загрузка demo безопасна: seed пропускает существующую организацию. Для новой установки удалите volume только если данные не нужны.

Контейнер приложения применяет версионные миграции (`drizzle/`, для БД, созданных старым `push`, — baseline без изменения данных) и загружает демонстрационные данные перед стартом. Healthcheck: `/api/health`. Для сквозной проверки API после запуска: `npx tsx --env-file=.env scripts/smoke.ts` (добавляет тестовый объект).

### Без Docker

`npm ci && npm run db:migrate && npx tsx --env-file=.env scripts/seed.ts && npm run dev`. Нужен PostgreSQL и заполненный DATABASE_URL.

### Сквозной сценарий

Войти директором → создать объект → в карточке добавить этап/работу и бюджет → добавить материал, склад и поставщика → создать заявку → согласовать → принять на склад → списать со склада → обновить прогресс работы → зарегистрировать расход → посмотреть отклонение в бюджете и скачать CSV-отчет.

## Что действительно работает

- Реальные связанные записи проектов, WBS, бюджетных статей, расходов, материалов, складских движений, заявок, договоров и контрагентов в PostgreSQL.
- Транзакционная приемка с частичной поставкой; проверка остатка под advisory lock перед списанием; стоимость списания отражается в расходах.
- Согласование заявки директором, аудит изменений, оповещения при расходе сверх бюджета и низком остатке.
- Панель директора, карточка объекта, формы, поиск по загруженным данным, CSV-экспорт, роль директора и базовый ACL на запись по проекту.
- Демо: три объекта (нормальный, перерасход, задержки), дефицит арматуры, просроченная поставка и работа.

## Важно: границы текущей версии

Это **функциональный фундамент, не завершенная «1С для стройки» и не готовая production-система**. Не реализованы: полнофункциональный Gantt/критический путь, сметные стандарты и версионирование смет, банковская интеграция, регламентированный бухгалтерский и налоговый учет, обработка фото и файлов, универсальные маршруты согласований, Excel/PDF-импорт и экспорт, проверка задолженности, техника, табель, резервирование партий и автоматические бэкапы. Интерфейс отчета CSV, а не официальный регламентированный документ. ERP_PRIVATE_MODE должен быть `true` на любой установке с реальными данными. До production необходимы изоляция арендаторов во всех селекторах, расширенный RBAC, защищенный ingress/HTTPS, миграционный процесс вместо `push`, тесты и мониторинг.

## Структура

- `src/db/schema.ts` — модель PostgreSQL, ключи и индексы.
- `src/lib/seed.ts` — демонстрационные данные.
- `src/lib/overview.ts` — серверные агрегаты и правила оповещений.
- `src/lib/session.ts` — хеширование паролей и подписанные сессии.
- `src/app/api/v1/[resource]/route.ts` — версионированный API и транзакционные команды.
- `src/components/workspace.tsx` — ERP-интерфейс.
- `docs/` — архитектура, БД, API, права, развертывание, правила, разработка, резервирование.

Управленческие показатели не являются бухгалтерскими регистрами. Интеграция с учетной системой проектируется отдельно. AI не участвует в записи финансовых данных.
