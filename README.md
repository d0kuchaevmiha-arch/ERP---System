# ERP «Энерготех» — управление строительными объектами

> **EN:** Construction management ERP (budgets, WBS, procurement, warehouse, contracts) built as a Next.js 16 / PostgreSQL 16 web app, plus a Windows desktop client (Electron) with a local replica and **offline data entry with server synchronisation** (operation outbox, conflict resolution, offline login). Tests run against a real PostgreSQL 16.

Веб-ERP для управленческого учёта строительной компании и десктоп-клиент для Windows, который работает **без интернета**: данные вводятся локально и уходят на сервер, когда связь появляется.

Версия **0.5.1**. История изменений — [CHANGELOG.md](CHANGELOG.md). Как запустить — [docs/RUN.md](docs/RUN.md).

## Что делает система

- **Объекты и работы:** иерархия работ, бюджет, расходы, план и факт, прогресс с историей фактов.
- **Закупки:** заявки на материалы, согласование директором, приёмка поставки (частичная, с проверкой заказа).
- **Склад:** приход, возврат, выдача, списание; остаток проверяется под блокировкой до списания; низкий остаток — уведомление.
- **Договоры и контрагенты**, отчёт по объекту в CSV.
- **Пользователи и доступ:** роли, доступ к объекту «просмотр / ввод», блокировка с мгновенным отзывом сессий, временные пароли.
- **Реальное время:** изменения коллег видны в браузере без перезагрузки (LISTEN/NOTIFY → SSE, задержка — доли секунды).
- **Десктоп (Windows 10/11):** установщик `.exe`, встроенный PostgreSQL, локальная реплика данных своих объектов; ввод без связи (выполнение, расходы, заявки, движения склада, приёмка); очередь отправки с пометкой «не синхронизировано»; отклонённое откатывается и показывается с причиной; спорное (нехватка остатка, приёмка сверх заказа) идёт ответственным на экран «Требует решения».

## Технологии

| Область | Стек |
|---|---|
| Язык | TypeScript (strict) |
| Веб и API | Next.js 16 (App Router), React 19, Tailwind CSS 4 |
| Данные | PostgreSQL 16, Drizzle ORM, версионные миграции (без `push`) |
| Валидация | Zod (на сервере — обязательно) |
| Реальное время | PostgreSQL LISTEN/NOTIFY, Server-Sent Events |
| Десктоп | Electron 44, встроенный PostgreSQL 16, electron-builder (NSIS), esbuild |
| Безопасность | scrypt (пароли), Windows DPAPI (секреты на ноутбуке), сессии с `session_version`, лимит попыток входа в БД, идемпотентность по `Idempotency-Key` |
| Тесты | Vitest (интеграционные на настоящем PostgreSQL), Playwright (E2E собранного десктопа) |
| Инфраструктура | Docker, Docker Compose |

## Архитектура в двух словах

- **Одна точка записи.** Все изменения идут через доменные команды (`src/server/domain/commands/`): роль → Zod → проверка доступа к объекту → транзакция → аудит → журнал изменений. HTTP-API и синхронизация десктопа вызывают один и тот же реестр команд.
- **Офлайн-синхронизация.** Клиент отправляет *команды* (очередь outbox), а не готовые строки. Сервер проверяет каждую по тем же правилам. Отклонённое откатывается на клиенте; спорное становится задачей для человека. У каждого факта хранится происхождение: устройство, время ввода, время приёма сервером.
- **Деньги** — `NUMERIC` и строки, никаких float как источника истины.
- **Гонки** закрыты условными UPDATE, `SELECT … FOR UPDATE`, advisory lock на складе и оптимистической блокировкой `version` (ответ 409).

Подробно: [docs/architecture.md](docs/architecture.md); спецификация офлайн-синхронизации — [docs/superpowers/specs/2026-09-29-desktop-offline-sync-design.md](docs/superpowers/specs/2026-09-29-desktop-offline-sync-design.md).

## Структура репозитория

- `src/db/schema.ts` — модель PostgreSQL; `drizzle/` — версионные миграции; `drizzle-client/` — миграции локальной БД десктопа.
- `src/server/domain/` — команды, реестр `registry.ts`, идемпотентность, версии, разбор конфликтов.
- `src/server/sync/` — офлайн-синхронизация на сервере: scope, snapshot, pull, push.
- `src/server/read/` — чтение с учётом организации и доступа.
- `src/server/auth/` — пароли, сессии, вход устройства, лимит попыток.
- `src/client/` — десктоп-клиент: локальная БД, sync-agent, очередь, офлайн-вход.
- `src/app/api/` — тонкие HTTP-обработчики.
- `desktop/` — оболочка Electron (главный процесс, preload, экраны подключения и входа, сборка).
- `test/` — интеграционные тесты на PostgreSQL 16, в том числе 12 сценариев синхронизации с двумя эмулированными клиентами (`test/sync-scenarios.test.ts`).
- `e2e/` — Playwright: собранное приложение, офлайн-сценарии, установщик.
- `scripts/` — `smoke.ts` (сквозная проверка API против работающего сервера), `migrate.ts`, `seed.ts`, `check-desktop-package.mjs` (сборка не содержит секретов).

```bash
npm run test:db:up   # тестовый PostgreSQL 16 на 127.0.0.1:54329

```

## Честно о границах

Это **функциональный фундамент, а не готовая production-система** и не замена учётным программам. Не реализованы: полноценный Gantt и критический путь, сметные нормативы, банковская интеграция, регламентированный бухгалтерский и налоговый учёт, файлы и фото, Excel/PDF-импорт и экспорт, табель, техника, автоматические бэкапы.

Не проверено в этой среде: чистая установка на Windows (SmartScreen, антивирус, корпоративный HTTPS) — см. чек-лист в [docs/desktop.md](docs/desktop.md). До выхода в сеть организации нужны HTTPS-прокси, бэкапы по расписанию и мониторинг ([docs/deployment.md](docs/deployment.md), [docs/backup.md](docs/backup.md)).
