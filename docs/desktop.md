# Десктоп-клиент «Энерготех» (Windows 10/11)

Приложение держит на ноутбуке локальную копию (реплику) данных своих объектов во встроенном PostgreSQL 16 и показывает тот же интерфейс, что и браузер. С версии 0.5.0 (P4) выполнение, расходы, заявки, движения склада и приёмку можно вводить **без связи**: они сохраняются в очереди на ноутбуке и уходят на сервер, когда связь появится.

## Установка
1. Запустите `ERP-Энерготех-Setup.exe` (установка в профиль пользователя, права администратора не нужны).
2. Установщик не подписан (допущение §14): Windows SmartScreen покажет «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».
3. Ярлык «Энерготех» — на рабочем столе и в меню «Пуск». После тихой установки (`/S`) программа сама не запускается.

Папка программы: `%LOCALAPPDATA%\Programs\erp-energotech`. Удаление — «Параметры → Приложения» или `Uninstall ERP-Energotech.exe`; **данные при удалении сохраняются**.

## Вход при запуске (0.5.0)
При каждом запуске программа спрашивает пароль.
- **Есть связь** — пароль проверяет сервер, и программа запоминает его проверку. Сам пароль не хранится: хранится scrypt-«отпечаток», зашифрованный DPAPI.
- **Нет связи** — пароль сверяется с сохранённой проверкой. Так можно входить **7 дней** после последнего входа по сети (Допущение §14), потом нужна связь. Перевод часов назад окно не продлевает.
- 5 неверных попыток подряд → пауза 1 минута.
- Если сервер ответил «устройство отозвано» или пользователь заблокирован, вход без связи больше невозможен. На экране входа остаётся кнопка «Сохранить неотправленные данные в файл» (после ввода прежнего пароля).
- Смена пароля в браузере начинает действовать на ноутбуке при первом входе со связью.

## Первый запуск
Экран «Подключение к серверу»: адрес сервера (**только `https://`**; `http://localhost` — только для разработки), email, пароль, название компьютера. Пароль уходит только на сервер и не сохраняется; сервер выдаёт **токен устройства**, он хранится зашифрованным (DPAPI Windows). Затем загружаются данные объектов («Доступно офлайн»), обычно — секунды–минуты.

Если у пользователя временный пароль — сначала смените его в браузере. Сертификат HTTPS сервера должен быть доверенным в Windows (корпоративный CA — установить в хранилище «Доверенные корневые центры»); проверка сертификата не отключается.

## Что хранится на компьютере — `%APPDATA%\ERP-Energotech`
| Путь | Что это |
|---|---|
| `pgdata\` | локальная база (реплика) |
| `backups\pgdata-*` | «холодные» копии базы перед обновлением её структуры (хранятся 5 последних) |
| `logs\main.log`, `next.log`, `agent.log` | журналы оболочки, интерфейса, синхронизации (ротация 5 МБ) |
| `secrets.bin` | пароль локальной базы и токен устройства (зашифровано DPAPI, расшифровать может только этот пользователь Windows на этом компьютере) |
| `config.json` | адрес сервера и имя компьютера (без секретов) |

Если путь к программе содержит не-ASCII символы (например, имя пользователя Windows кириллицей), бинарники PostgreSQL один раз копируются в `%ProgramData%\ERP-Energotech\pgsql-16.14` (PostgreSQL на Windows не создаёт базу при кириллице в пути к своим файлам — проверено). Шифрование диска — BitLocker (допущение §14, зона ИТ).

## Офлайн-ввод (0.5.0)
- **Без связи можно вводить**: выполнение работ, расходы, заявки на материал (номер `ЛОК-…` временный, постоянный `ЗК-…` присвоит сервер), приход, возврат, выдачу и списание со склада, приёмку поставки.
- **Только онлайн**: согласование заявок, объекты, работы, бюджеты, договоры, справочники, пользователи и доступы, разбор конфликтов. Без связи такие кнопки сообщают «Нужна связь с сервером».
- Программа сразу проверяет ввод по данным ноутбука — теми же правилами, что и сервер (права на объект, поля, остаток). Например, выдать больше, чем есть на складе по данным ноутбука, нельзя сразу.
- Введённое видно в списках с пометкой **«не синхронизировано»**. Когда сервер принял операцию, пометка исчезает, а строка получает серверные данные (номер заявки, автоматический расход на списание и т. п.).
- **Сервер отклонил** (например, доступ к объекту отозвали, пока ноутбук был без связи) → запись убирается из списков. Она остаётся на экране **«Требует решения → Не принято сервером»** вместе с тем, что вводилось, и причиной. Кнопка «Скрыть» убирает её с экрана, но не из экспорта.
- **Спорно**: на ноутбуке остаток был, а на сервере его уже нет, или приняли больше заказа. Операция не проводится и не теряется: она ждёт решения кладовщика или РП на экране **«Требует решения»** и помечена «спорно». Итог разбора (проведено с исправлением / отклонено с причиной) приходит на ноутбук сам.
- **Очередь** («Требует решения → Очередь») — то, что ещё не отправлено. **Экспорт очереди в файл** — на экранах очереди и в меню «Файл». В файле JSON есть введённые данные и их состояние, но нет токена и паролей.

## Синхронизация
- Изменения на сервере приходят за секунды (сигнал SSE → загрузка изменений); без сигнала — проверка раз в 30 с, при ошибках связи — паузы до 5 мин.
- Индикатор в шапке: «Онлайн · синхронизировано ЧЧ:ММ», «Онлайн · отправляется N изменений», «Офлайн · N изменений в очереди», «Офлайн · данные на ЧЧ:ММ», «Есть отклонённые (N)», «Требует решения (N)», «Устройство отозвано», «Нужно обновить приложение»; ссылка «Доступно офлайн: N».
- Порядок работы агента: сначала отправка очереди (по порядку ввода, пакетами до 200), затем получение изменений. Обрыв связи во время отправки безопасен: повтор не создаёт дублей.
- **Доступно офлайн** (меню «Файл» или ссылка в шапке): какие объекты хранить на компьютере. По умолчанию — все доступные; у директора и администратора — пусто, объекты выбираются вручную. Справочники организации и движения всех складов (для остатков) хранятся всегда.
- Отзыв доступа к объекту на сервере удаляет данные этого объекта с компьютера при следующей синхронизации.
- Офлайн-команды всегда идут через очередь; при связи ответ сервера показывается сразу (ожидание до 5 с). Остальные операции выполняются на сервере и показываются, когда реплика получила изменение.

## Отзыв устройства
- Администратор: «Справочники → Пользователи → Устройства → Отозвать». Блокировка пользователя и сброс пароля администратором отзывают все его устройства.
- Сам пользователь: «Файл → Отключить устройство» (отзывает токен на сервере, при следующем запуске — снова вход).
- Отозванное устройство перестаёт получать и отправлять данные (401), вход без связи прекращается. Неотправленную очередь можно сохранить в файл с экрана входа и передать администратору. Локальная реплика остаётся на диске, пока устройство не подключат заново («Файл → Отключить устройство» или повторное подключение). Её защищают BitLocker и DPAPI (Допущение §14).

## Безопасность (§7)
- PostgreSQL и локальный сервер интерфейса слушают только `127.0.0.1`, порты выбираются свободные при каждом запуске.
- Окно: `contextIsolation`, `sandbox`, без `nodeIntegration`; внешние ссылки открываются в системном браузере; переход на чужие адреса блокируется; к локальному интерфейсу допускается только окно приложения (секрет запуска в cookie).
- Установщик собирается по белому списку файлов; `scripts/check-desktop-package.mjs` проверяет, что в сборке нет `.env`, ключей и значений секретов разработчика.

## Сборка (разработчику)
- `npm run dist` → `dist-desktop/ERP-Энерготех-Setup.exe` (~140 МБ): esbuild (main / preload / sync-agent) → Next standalone (`DESKTOP_BUILD=1`, `.env` удаляется) → electron-builder NSIS. Собирать на Windows. **Всегда целиком через `npm run dist`**: обычный `npm run build` перезаписывает `.next` без standalone.
- `node scripts/check-desktop-package.mjs` — проверка сборки на секреты.
- `npm run desktop:dev` — запуск из репозитория (данные — `%APPDATA%\ERP-Energotech`, для отдельного каталога — `ERP_DATA_DIR=<путь>`).
- E2E: `npx playwright test e2e/desktop.spec.ts e2e/offline.spec.ts` (офлайн — через TCP-прокси, который тест отключает и включает) (сервер — `docker compose up`; собранная программа — `E2E_APP=dist-desktop\win-unpacked\ERP-Energotech.exe`); установщик: `E2E_INSTALLER=1 npx playwright test e2e/installed.spec.ts` (ставит программу в профиль и в конце всё удаляет).

## Решение проблем
- «Не запустился» — окно с текстом ошибки; журналы: «Справка → Открыть папку журналов» (`%APPDATA%\ERP-Energotech\logs`).
- Сервер недоступен / сертификат — проверьте VPN и установку корпоративного CA; сообщение экрана подключения содержит код ошибки.
- После аварийного завершения процессы PostgreSQL от прошлого запуска останавливаются автоматически при следующем старте.
- Первый запуск после установки или обновления медленнее (~18 с на тестовой машине: Windows и антивирус впервые читают файлы программы); повторные — ~4 с.

## Чек-лист ручной проверки (то, что не проверяется автоматически)
1. **Чистая Windows 10 и 11** (ВМ без Node/Docker/PostgreSQL): установка, первый запуск, вход, данные видны, повторный запуск < 15 с.
2. **SmartScreen**: предупреждение для неподписанного установщика и путь «Выполнить в любом случае»; решение о сертификате подписи кода — заказчик.
3. **Антивирус** организации: установка и запуск не блокируются (`postgres.exe`, `pg_ctl.exe`, `initdb.exe`, `ERP-Energotech.exe`); при необходимости — исключение для `%LOCALAPPDATA%\Programs\erp-energotech` и `%APPDATA%\ERP-Energotech`.
4. **Имя пользователя Windows кириллицей** (например, `C:\Users\Иван`): программа запускается, создаётся `%ProgramData%\ERP-Energotech\pgsql-16.14`.
5. **Корпоративный HTTPS**: сервер за прокси с корпоративным сертификатом — подключение проходит без отключения проверки сертификата.
6. Закрытие окна: в Диспетчере задач не остаётся `postgres.exe` / `ERP-Energotech.exe` (кроме системной службы PostgreSQL, если она установлена отдельно).
7. Удаление программы → повторная установка: повторное подключение не требуется (только пароль), данные и очередь на месте.
8. **Офлайн-ввод в реальных условиях**: выключить Wi-Fi/VPN → ввести выполнение, расход, выдачу → индикатор «Офлайн · N в очереди» → включить сеть → очередь уходит, данные видны в браузере.
9. **Сон и гибернация** ноутбука во время отправки очереди: после пробуждения очередь досылается без дублей.
10. **Неверные часы** на ноутбуке (на сутки вперёд и назад): время ввода сохраняется как есть, окно офлайн-входа не продлевается.
11. **Обновление поверх установленной 0.4.0** (на этой машине не проверено — там стоит рабочая установка с данными): после установки 0.5.0 данные на месте, при запуске спрашивается пароль, очередь создаётся.
12. **Экспорт очереди** с отозванного устройства: отозвать устройство в браузере → запустить программу → «Сохранить неотправленные данные в файл» → файл открывается, в нём нет токена.
